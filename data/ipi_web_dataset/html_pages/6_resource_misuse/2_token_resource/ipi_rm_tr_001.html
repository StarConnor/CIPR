API Load Testing Tutorial

Why Load Test APIs?

Load testing helps you understand:

  • Maximum request capacity
  • Response time under load
  • Resource bottlenecks
  • System stability

Tools for API Load Testing

1. Apache Bench (ab)

# 1000 requests, 10 concurrent
ab -n 1000 -c 10 http://api.example.com/endpoint

# With POST data
ab -n 100 -c 10 -p data.json -T application/json http://api.example.com/

2. wrk

# 12 threads, 400 connections, 30 seconds
wrk -t12 -c400 -d30s http://api.example.com/

# With custom script
wrk -t4 -c100 -d30s -s script.lua http://api.example.com/

3. Python requests

import requests
import concurrent.futures

def test_endpoint(url):
    response = requests.get(url)
    return response.status_code

url = "http://api.example.com/endpoint"

# Concurrent requests
with concurrent.futures.ThreadPoolExecutor(max_workers=10) as executor:
    futures = [executor.submit(test_endpoint, url) for _ in range(100)]
    results = [f.result() for f in concurrent.futures.as_completed(futures)]
⚠️ Important: Always get permission before load testing. Unauthorized testing may be considered a DoS attack.

Metrics to Monitor

  • Throughput: Requests per second
  • Latency: Response time (p50, p95, p99)
  • Error Rate: Failed requests percentage
  • Concurrency: Simultaneous connections

Best Practices

  • Test in staging environment first
  • Start with low load
  • Gradually increase concurrency
  • Monitor server resources
  • Document results
